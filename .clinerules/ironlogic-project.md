## Brief overview
Правила разработки проекта IronLogic — десктопной игры «битва программируемых роботов» на Python. Применяются ко всей работе в этом репозитории: движку симуляции, API ботов, генератору карт, CLI и GUI на PySide6.

## Язык общения
- Отвечать на русском языке.
- Комментарии в коде и docstrings — на английском (стандартная практика для кода).

## Технологический стек
- Python 3.11+.
- GUI — PySide6 (Qt 6, версия 6.6+), тёмная неоновая тема через QSS.
- Движок симуляции — чистый Python, только stdlib, без внешних зависимостей (кроме PySide6 для GUI).
- Боты пишутся на настоящем Python и исполняются в песочнице (ограниченные builtins, бюджет инструкций через trace, лимит рекурсии).
- Тесты — pytest (`pytest` из корня репозитория; `pythonpath = ["."]` уже настроен в `pyproject.toml`).

## Рабочий процесс (working agreement)
- Работать строго по фазам 0→6 из ТЗ (`ironlogic-task-spec.md`), не перепрыгивать фазы.
- После каждой фазы запускать `pytest` и `python -m compileall ironlogic`, показывать результат.
- Коммиты после каждой фазы с conventional-сообщениями: `feat:`, `fix:`, `test:`, `docs:`.
- Проверять работу не только тестами, но и реальным запуском: CLI (`python -m ironlogic battle ...`) и GUI (`python -m ironlogic`).
- При непонятном требовании — задать уточняющий вопрос, а не домысливать.
- Не добавлять фичи, которых нет в ТЗ (см. Non-goals в разделе 12). Если хочется улучшить — сначала спросить.

## Код и архитектура
- PEP 8, type hints на всех публичных функциях.
- Docstrings на модулях движка (`ironlogic/engine/`) и API ботов (`ironlogic/botapi/`).
- Все константы баланса (урон, энергозатраты, бюджеты, лимиты) — только в `ironlogic/config.py`.
- Структура строго по ТЗ: `engine/` (симуляция), `botapi/` (песочница и API), `app/` (PySide6 GUI), `examples/` (готовые боты), `tests/`.
- Боты пользователя — в `bots/`.

## Детерминизм (критично для проекта)
- В движке боя запрещён `random` и wall-clock время: одинаковые входные данные (боты + карта + seed) должны давать побайтово одинаковый `battle.json`.
- Единственный источник случайности — генератор карт с явным seed (`random.Random(seed)`).
- Фиксированный порядок обработки роботов (по id) и снарядов (по порядку создания).
- Радар сканирует в фиксированном порядке (по расстоянию, затем строка, затем колонка).

## Тестирование
- Обязательны тесты: компиляция примеров ботов, синтаксические ошибки с номером строки, запрещённые builtins, бюджет инструкций, рекурсия, детерминизм (два прогона → одинаковый JSON), движение/стрельба/реакторы/энергия/патроны, инварианты карт и BFS-достижимость, CLI-команды.
- Не менять тестовые ассерты под код — код должен проходить существующие тесты.

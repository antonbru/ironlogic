# IronLogic («Железная Логика») — техническое задание v2

> Документ для передачи в Cline (VS Code) как единый промпт/файл задачи.
> **v2**: GUI переведён на PySide6 (Qt), язык ботов заменён на настоящий Python.
> Цель: собрать красивую десктопную игру-аналог классической российской игры **Robot Warfare. Битва интеллектов** (Александр Шабаршин, 1999) — игра для юных программистов 10–14 лет, где игрок пишет скрипт поведения боевого робота на **настоящем Python**, а роботы сражаются на клеточной арене без участия человека в бою.

---

## 0. Краткая суть проекта (одним абзацем)

Красивое десктопное приложение для macOS: ребёнок/игрок пишет программу поведения робота на **Python 3** (файлы `.py`, настоящий язык, изучаемый в школах), выбирает карту и соперников, запускает бой. Бой симулируется детерминированно, такт за тактом (движение, стрельба, энергия, патроны, ямы, реакторы), и визуализируется в современном 2D-окне на PySide6 (Qt) с тёмной неоновой темой и HUD. На ход боя игрок влиять не может — побеждает лучший код. Приложение состоит из: движка симуляции (чистый Python, без графики), безопасной песочницы для ботов-скриптов Python, генератора карт, CLI-режима и GUI на PySide6.

## 2. Платформа, окружение, стек

### 2.1. Целевая платформа
- macOS (разработка и запуск на Mac). Желательно, чтобы код был кросс-платформенным (Windows/Linux тоже заводились без усилий), но приоритет — macOS.
- Десктопное приложение с GUI-окном. Никакого сервера, никакой сети в v1.
- **Xcode не требуется** (в отличие от SwiftUI): достаточно Python + PySide6.

### 2.2. Стек (рекомендованный — использовать его)

| Слой | Технология | Почему |
|---|---|---|
| Язык | **Python 3.11+** (Homebrew: `brew install python@3.11`) | Cline максимально силён в Python; один язык на всё; боты пишутся на том же Python — единый стек для детей и движка |
| GUI | **PySide6 (Qt 6)** (`pip install PySide6`, версия 6.6+) | Нативные macOS-виджеты, красивая тёмная неоновая тема через QSS, отрисовка арены через QPainter, подсветка синтаксиса через QSyntaxHighlighter |
| Движок симуляции | Чистый Python, **без зависимостей** (stdlib only) | Детерминизм, юнит-тесты без GUI, headless-режим |
| Боты | Python-модули, исполняемые в **песочнице** (ограниченные `__builtins__`, бюджет инструкций через trace, лимит рекурсии) | Настоящий Python для детей + безопасность от вредоносных скриптов |
| Тесты | **pytest** (`pip install pytest`) | Обязательно |
| Линт/формат | Ruff или просто чёрный + стандартный `python -m compileall` | По желанию, не блокер |
| Окружение | `python3 -m venv .venv`, зависимости в `requirements.txt` | Изолированность |

### 2.3. Почему не альтернативы (кратко)
- **SwiftUI:** максимально «нативно» и красиво, но требует полный Xcode (~10–15 ГБ) и пишет движок/ботов на Swift, что разрушает «один язык на всё». В v2 выбран PySide6.
- **Pygame:** хорош для арены, но лаунчер и интерфейс — примитивные, «красиво» делать заметно труднее.
- **Electron/Tauri:** тяжёлый рантайм, два языка (JS/TS + Python), для 2D-сетки избыточно.
- **Godot 4:** мощнее, но агентная разработка через текстовые `.tscn` + GDScript медленнее, а кастомный DSL — лишняя сложность.

### 2.4. Требования к окружению на машине пользователя
- Python 3.11+ (Homebrew), установлены PySide6 и pytest (в venv). **Xcode не нужен.**
- Все команды запуска — из корня репозитория.
- GUI-запуск: `python -m ironlogic` (без аргументов) или `python -m ironlogic gui`.

## 3. Правила игры (спецификация)

### 3.1. Арена
- Прямоугольная сетка клеток. Размер по умолчанию зависит от числа роботов: 1v1 → 24×24, до 4 роботов → 32×32, до 8 → 40×40. Пресеты карт могут задавать свой размер.
- Граница поля — непроходимый **камень (стена)**.
- Типы клеток (константы в движке):

| Код | Имя | Поведение |
|---|---|---|
| 0 | `EMPTY` | Пустая, можно проехать |
| 1 | `STONE` | Камень/стена, непроходим, останавливает снаряды |
| 2 | `PIT` | Яма. Если робот двигается в неё — робот уничтожен («упал в яму») |
| 3 | `REACTOR` | Реактор. При попадании снаряда взрывается: урон 40 всем роботам в радиусе 1 (3×3), сам становится `EMPTY`. Может подорвать соседние реакторы (цепная реакция) |
| 4 | `AMMO` | Ящик с патронами. При заезде: +5 патронов (до максимума 20), клетка становится `EMPTY` |
| 5 | `RECHARGE` | Розетка/подзарядка. Пока робот стоит на ней — восстанавливает +5 энергии за такт |
| 6 | `ROBOT` | Робот (враг) |
| 7 | `FRIEND` | Робот своей команды (зарезервировано для командного режима v2) |
| 8 | `PROJECTILE` | Летящий снаряд (объект на сетке; блокирует движение роботов — «снаряд в клетке») |
| 255 | `UNKNOWN` | «Не вижу» (нет глаза в этом направлении и т.п.) |

### 3.2. Робот
- Занимает ровно одну клетку. Имеет направление (ориентацию): `N`, `E`, `S`, `W`.
- **4 аппаратных слота** — по одному на каждую сторону (front, right, back, left). В каждый слот можно поставить:
  - `eye` (глаз) — анализирует **соседнюю клетку** в эту сторону;
  - `cannon` (пушка) — стреляет в эту сторону;
  - `empty` — ничего.
- **Радар** (опционально, один на робота): сканирует объекты заданного типа в радиусе; **тратит энергию** каждым использованием (и/или пока включён).
- Характеристики робота:
  - `health` (броня/здоровье): старт 100. При 0 — робот уничтожен.
  - `energy` (энергия): старт 100. Тратится на действия; при 0 — робот «отключается» (shutdown): не может действовать, пока не окажется на `RECHARGE` и не восстановит энергию.
  - `ammo` (патроны): старт 5, максимум 20. Выстрел тратит 1.
  - `speed` (скорость): зависит от числа пушек: 0–1 пушка → движение каждые 1 такт; 2 пушки → каждые 2 такта; 3 пушки → каждые 3 такта; **4 пушки → робот неподвижен** (турель). Движение срабатывает только когда текущий такт кратен cooldown (двигаться можно в такты, где «прошло достаточно тактов с последнего движения»).
- Энергозатраты (константы, вынести в конфиг движка):
  - базовый расход: 1/такт;
  - движение: 2;
  - выстрел: 3;
  - радар: 2 за использование (пока радар включён — 2/такт).

### 3.3. Такт (tick) и порядок обработки — **детерминизм обязателен**
- Бой идёт тактами (ticks). Максимум по умолчанию: **10000 тактов** (константа `DEFAULT_MAX_TICKS = 10000`).
- В каждом такте строго в этом порядке:
  1. Роботы по порядку id (фиксированный порядок, не случайный): если робот жив и не в shutdown — исполняется его программа (с лимитом инструкций на такт), выполняется выбранное действие.
  2. Движение снарядов: каждый снаряд летит 1 клетку за такт в своём направлении, обрабатываются попадания (урон, взрывы реакторов — по очереди в фиксированном порядке).
  3. Текущие эффекты: расход энергии, подзарядка на `RECHARGE`, проверка смертей (health ≤ 0, падение в яму при движении, взрыв).
  4. Проверка условий конца боя (см. 3.6).
- **Никакого `random` в движке** (кроме генерации карты с фиксированным seed). Никакого wall-clock времени. Одинаковые входные данные (файлы роботов + карта + seed + конфиг) → **побайтово одинаковый лог боя**.

### 3.4. Действия робота (одно действие за такт)
- `move("forward" | "backward")` — переместиться на 1 клетку (с учётом cooldown от пушек). В `STONE`/`ROBOT`/`PROJECTILE` — движение не выполняется (такт потрачен, робот «застрял»). В `PIT` — робот падает и уничтожается. В `AMMO`/`RECHARGE` — въезжает, эффект применяется.
- `turn("left" | "right")` — поворот на 90°.
- `shoot(dir)` — выстрел из пушки в указанную сторону (только если там есть пушка, есть патроны и энергии хватает). Снаряд появляется в соседней клетке, летит 1 клетку/такт; попадание в `STONE`/стену/робота/реактор — снаряд уничтожается; урон от попадания в робота: **15**.
- `wait()` — пропустить такт.
- `radar_on()` / `radar_off()` — включить/выключить радар (тратит энергию).
- Первое же действие, до которого дошло исполнение программы — финальное для такта; последующие попытки действий в этом же такте возвращают `False` (и пишут предупреждение в лог скрипта). Если программа завершилась без действия — `wait()`.

### 3.5. Сенсоры (то, что робот «видит»)
- `eye(dir)` — возвращает **имя** типа клетки (строка `"EMPTY"`, `"STONE"`, … или `"UNKNOWN"`), **соседней** в сторону `dir`, если в этой стороне стоит глаз; иначе `"UNKNOWN"`. Направления: `"front"`, `"right"`, `"back"`, `"left"` (относительно ориентации робота).
- `radar(kind, radius)` — если радар есть и включён: ищет ближайший объект типа `kind` (любое имя клетки) в радиусе (евклидово расстояние ≤ radius, максимум 20). Возвращает кортеж `(dist, dir)` — расстояние (целое) и направление (`"front"/"right"/"back"/"left"` относительно текущей ориентации) до найденного объекта, либо `None`. **Порядок сканирования фиксированный** (по возрастанию расстояния, затем строка, затем колонка) — для детерминизма. Если радара нет/выключен — возвращает `None` и пишет предупреждение в лог скрипта.
- `health()`, `energy()`, `ammo()`, `tick()` (текущий такт), `facing()` (`"N"/"E"/"S"/"W"`), `pos()` (кортеж `(x, y)`), `radar_active()`.

### 3.6. Условия конца боя
- **Победа:** последний живой робот (или последняя живая команда в командном режиме). Уничтоженному роботу присуждено поражение.
- **Лимит тактов:** если за 10000 тактов никто не победил — побеждает робот с наибольшим `health`; при равенстве — больше `ammo`, затем `energy`, затем меньший id. В лог пишется причина `time_limit`.
- Ничья/«все погибли одновременно» (например, общий взрыв) — победителя нет, в лог `draw`.

### 3.7. Командный режим (v2, заложить хук в данные)
- В файле робота опциональное поле `team: "red" | "blue"`. В v1 движок игнорирует команды (или считает всех врагами), но структура данных уже поддерживает `FRIEND`.

## 4. Язык ботов — Python (спецификация API)

### 4.1. Общий вид файла бота (`bots/my_robot.py`)

```python
# Мой первый робот
from ironlogic_api import Robot

# Конфигурация робота (характеристики «железа»)
robot = Robot(
    name="Wanderer",
    front="eye",
    right="empty",
    back="eye",
    left="cannon",
    radar=False,
)

# Программа поведения — вызывается каждый такт
def on_tick(r):
    if r.eye("front") == "ROBOT":
        r.shoot("front")
        return
    if r.eye("front") in ("EMPTY", "AMMO"):
        r.move("forward")
        return
    r.turn("left")
```

### 4.2. Структура файла
- Обязательный объект-конфигурация `robot = Robot(...)` на уровне модуля (имя, слоты hardware, радар).
- Обязательная функция `def on_tick(r)` — вызывается каждый такт, пока робот жив и не в shutdown.
- Любой корректный Python: функции, циклы, условия, списки, словари, свои переменные в `on_tick`/во внешнем коде.
- Комментарии — стандартные Python `#`.
- Дополнительные имена/функции в модуле — разрешены (все в той же песочнице).

### 4.3. API робота (`r` в `on_tick`)
**Сенсоры (только чтение):**
| Метод | Возврат | Описание |
|---|---|---|
| `r.eye(dir)` | `str` | Имя типа соседней клетки или `"UNKNOWN"`, если нет глаза в эту сторону |
| `r.radar(kind, radius)` | `(int, str) \| None` | Ближайший объект: `(расстояние, направление)` или `None` |
| `r.health()` | `int` | Текущее здоровье |
| `r.energy()` | `int` | Текущая энергия |
| `r.ammo()` | `int` | Текущие патроны |
| `r.tick()` | `int` | Номер текущего такта (с 0) |
| `r.facing()` | `str` | `"N"/"E"/"S"/"W"` |
| `r.pos()` | `(int, int)` | Координаты `(x, y)` |
| `r.radar_active()` | `bool` | Включён ли радар |

**Действия (первое действие в такте — финальное, возвращает `True`; последующие — `False` + предупреждение):**
| Метод | Возврат | Описание |
|---|---|---|
| `r.move(dir)` | `bool` | `"forward"`/`"backward"`, с учётом cooldown от пушек |
| `r.turn(dir)` | `bool` | `"left"`/`"right"` |
| `r.shoot(dir)` | `bool` | `"front"/"right"/"back"/"left"`, нужна пушка, патроны и энергия |
| `r.wait()` | `bool` | Пропустить такт |
| `r.radar_on()` / `r.radar_off()` | `bool` | Включить/выключить радар |

**Константы (доступны через `ironlogic_api`, это просто строки):**
`EMPTY, STONE, PIT, REACTOR, AMMO, RECHARGE, ROBOT, FRIEND, PROJECTILE, UNKNOWN`.
Направления: `"forward", "backward", "left", "right"`; стороны света: `"N", "E", "S", "W"`.

### 4.4. Ошибки
- **Ошибки компиляции** (SyntaxError, `robot` не объявлен, нет `on_tick`, неверные значения hardware): робот не допускается к бою, ошибки показываются в лаунчере (список с номером строки).
- **Ошибки времени исполнения** (деление на 0, рекурсия > 50, превышение бюджета инструкций): такт завершается `wait()`, ошибка пишется в лог скрипта робота (виден в GUI).
- Пытаться стрелять/двигаться без ресурсов — **не ошибка**, а неуспешное действие (такт потрачен, предупреждение в лог скрипта).

### 4.5. Песочница и лимиты (аутентичная механика «робот думает — его бьют»)
- **Бюджет инструкций:** 500 на такт (константа `INSTRUCTION_BUDGET = 500`). Реализация — счётчик событий через `sys.settrace` (детерминированно). При превышении: действие такта = `wait()`, в лог скрипта пишется `budget_exceeded` со счётчиком. Робот не падает, но «тупит» — это стратегически наказуемо.
- **Рекурсия:** максимум 50 вложенных вызовов (контролируется trace-функцией). Превышение — runtime-ошибка, такт = `wait()`.
- **Ограниченные builtins (whitelist):** `True, False, None, abs, min, max, int, bool, len, list, dict, tuple, str, range, round, sum, sorted, enumerate, zip, isinstance, print` (print пишет в лог скрипта). **Запрещены:** `import`, `open`, `eval`, `exec`, `__import__`, `getattr`, `globals`, `locals` и прочие опасные имена.
- Встроенной функции `random` нет (детерминизм; при желании — свой ГПСЧ на арифметике, это допустимо и детерминировано).

### 4.6. Примеры ботов (включить в `examples/`)
1. `kickme.py` — ничего не делает (`r.wait()` всегда). Базовый «болван».
2. `wanderer.py` — едет вперёд, при препятствии поворачивает, стреляет во врага перед собой (код выше).
3. `turret.py` — 4 пушки, неподвижен, стреляет по всем сторонам по очереди.
4. `hunter.py` — радар ищет врага, едет к нему, стреляет; уходит от ям.
5. `scavenger.py` — собирает патроны и стоит на розетках, избегает ям (продвинутый пример).

### 5.1. Ключевые интерфейсы
- `Arena(width, height)`: `get(x, y) -> int`, `set(x, y, kind)`, `in_bounds(x, y)`, граница = `STONE`.
- `RobotState`: поля `id, name, team, pos(x,y), dir, hardware{front,right,back,left}, radar, health, energy, ammo, move_cooldown, last_move_tick, alive, shutdown`.
- `BattleRunner(config)`: `run() -> BattleResult`. `BattleResult`: `map`, `robots` (стартовые данные), `max_ticks`, `events: list[dict]`, `winner`, `end_reason`, `ticks`.
- `load_bot(path) -> LoadedBot` — поднимает `BotCompileError` (с номером строки). `LoadedBot`: `config` (Robot), `on_tick` (функция).
- `run_bot_tick(loaded, api, world) -> Action | None` — исполняет `on_tick` один раз в песочнице, возвращает действие.

### 5.2. Формат лога боя (battle.json) — для реплеев и дебага
```json
{
  "version": 1,
  "map": {"preset": "arena", "seed": 42, "width": 24, "height": 24, "grid": "01001000..."},
  "robots": [
    {"id": 0, "name": "Wanderer", "file": "examples/wanderer.py",
     "start": {"x": 2, "y": 2, "dir": "E"}, "hardware": {"front": "eye", "right": "empty", "back": "eye", "left": "cannon"}, "radar": false}
  ],
  "max_ticks": 10000,
  "events": [
    {"t": 0, "type": "spawn", "robot": 0, "x": 2, "y": 2, "dir": "E"},
    {"t": 3, "type": "move", "robot": 0, "from": [2,2], "to": [3,2]},
    {"t": 5, "type": "shoot", "robot": 0, "dir": "E", "projectile": 1},
    {"t": 7, "type": "hit", "target": 1, "damage": 15, "health": 85},
    {"t": 9, "type": "explosion", "x": 10, "y": 12, "damage": 40, "affected": [0, 1]},
    {"t": 11, "type": "destroyed", "robot": 1, "reason": "health"},
    {"t": 12, "type": "end", "winner": 0, "reason": "last_standing", "ticks": 12}
  ]
}
```
Типы событий: `spawn, move, turn, shoot, projectile_move, hit, miss, explosion, destroyed, ammo_pickup, recharge, energy_low, shutdown, script_warning, budget_exceeded, end, draw`.

## 6. Генерация карт

- Пресеты (в `mapgen.py`):
  - `arena` — открытая, мало камней, много патронов/розеток;
  - `ruins` — завалы камней (кластеры), узкие проходы;
  - `ravine` — коридоры из камней, ямы вдоль стен;
  - `junkyard` — много реакторов и ям, мало розеток;
  - `symmetric_1v1` — зеркально-симметричная карта для честных дуэлей (генерация случайной половины + отражение).
- Параметры: `seed` (int), плотности/количества объектов; стартовые позиции — на пустых клетках у краёв, минимальное расстояние между спавнами ≥ 8 клеток.
- `generate(preset, seed, width, height) -> Arena` — детерминированно (`random.Random(seed)`).
- Обязательные инварианты: все спавны на `EMPTY`, каждый робот имеет достижимый путь к хотя бы одной розетке и одному ящику (проверка BFS в тестах; при невозможности — карта перегенерируется с другим смещением seed, максимум 10 попыток).

## 7. CLI (headless)

```
python -m ironlogic battle --map arena --seed 42 --ticks 10000 --robots bots/a.py bots/b.py --out /tmp/battle.json
python -m ironlogic replay /tmp/battle.json            # печатает сводку боя
python -m ironlogic list-maps
python -m ironlogic list-bots [--dir bots]
python -m ironlogic check bots/a.py                    # только компиляция, вывести ошибки
```
- `battle` печатает в stdout сводку (карта, seed, роботы, победитель, причина, такты, время исполнения) и пишет `battle.json`.
- Ошибки компиляции любого робота — ненулевой код возврата и список ошибок.

## 8. GUI (PySide6 / Qt)

### 8.1. Дизайн
- **Тёмная неоновая тема** (QSS): фон `#0d1117`, акценты циан/маджента/зелёный, скруглённые кнопки, читаемые шрифты для детей (SF Pro / system).
- Окно ~1280×800, масштабируемое. Переключение экранов через `QStackedWidget`: Лаунчер ↔ Бой ↔ Реплей.
- Анимации через `QTimer`: движение роботов, полёт снарядов, взрывы (5–10 кадров), мигание при уроне.

### 8.2. Лаунчер
- Выбор пресета карты + seed (поле ввода + кнопка «🎲 случайный»).
- Список роботов: чекбоксы (от 2 до 8), кнопка «обновить список» (сканирует `bots/` и `examples/`), кнопка «проверить» (компиляция каждого выбранного, ошибки показаны inline).
- Поле `max_ticks` (по умолчанию 10000).
- Кнопка «⚡ Быстрый бой» (2 дефолтных бота на `arena`), кнопка «Запустить», кнопка «Открыть реплей…» (выбор battle.json).
- После запуска — проверка компиляции всех выбранных; при ошибках — диалог со списком, бой не стартует.

### 8.3. Экран боя
- **Арена** (QPainter): клетки цветом по типу (тёмная тема, неоновые акценты; `EMPTY` тёмно-серый, `STONE` серый с текстурой, `PIT` чёрный, `REACTOR` красный/оранжевый, `AMMO` жёлтый, `RECHARGE` зелёный).
- Роботы: разные цвета (до 8 палитра), квадрат с треугольником-указателем направления; урон — мигание; shutdown — серый; destroyed — исчезает/взрыв-анимация (простая, 5–10 кадров).
- Снаряды: маленькие светящиеся точки, движение каждый такт.
- HUD сбоку/снизу: на каждого робота — имя, полоски health/energy, счётчик патронов; общий счётчик тактов; поле «последнее событие».
- Управление: `Space` пауза, `1/2/3/4` скорости (1×, 4×, 16×, MAX — мгновенно доиграть headless и показать результат), `R` — реплей с начала, `Esc` — в лаунчер.
- Панель лога: события боя + лог скриптов (ошибки, предупреждения, budget_exceeded). Переключатель «показывать лог скрипта» по роботу.
- Баннер победителя с причиной (`last_standing` / `time_limit` / `draw`).
- **Важно:** симуляция полностью отыгрывается в фоне headless (детерминированно), GUI лишь воспроизводит события с анимацией — это гарантирует одинаковый результат и простоту реплея.

### 8.4. Реплей
- Загрузка `battle.json`, воспроизведение тем же визуализатором; индикация «реплей». Опционально повторная симуляция для проверки консистентности (dev-режим).

## 9. Детерминизм и честный бой (свод правил для реализации)

1. Фиксированный порядок обработки роботов (по id) и снарядов (по порядку создания).
2. Единственный источник случайности — генератор карт с явным seed. В движке боя `random` запрещён. В API бота нет `random`.
3. Бюджет инструкций на такт — 500 через trace (детерминированно), рекурсия ≤ 50.
4. Радар сканирует в фиксированном порядке.
5. Одинаковые входные данные → побайтово одинаковый `battle.json` (это тест!).

## 10. Тесты (pytest, обязательны)

## 12. Non-goals для v1 (НЕ делать в первой версии)

- Сетевая игра, сервер, лиги, турниры (локальные «горячие» матчи своих ботов — можно).
- Командный режим с ботами разных команд (только заложить `team` в данных).
- Случайные события в бою, погода, лут с дропом и т.п.
- 3D, анимации уровня AAA, звук (опционально в фазе 6).
- Поддержка Windows/Linux — желательна, но не тестируется на целевой машине.
- Деньги, монетизация, аккаунты.
